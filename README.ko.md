XXD Panel 019는 Codex와 호환 에이전트를 위한 이미지 생성 Skill입니다. 피사체, 자세, 방향, 비례, 분리할 수 없는 관계를 알아볼 수 있는 레트로 모더니즘 평면 일러스트로 옮깁니다. 벡터 트레이싱도 아니고, 원본을 일반적인 기하 도형 아래 지워 버리는 구실도 아닙니다.

단순화는 잡음을 제거해야지 정체성을 제거해서는 안 됩니다.

## 왜 만들었나요

많은 사진-평면 일러스트 워크플로는 보편적인 시각 도구 상자로 수렴합니다. 사람은 얼굴 없는 실루엣이 되고, 실제 장소는 태양과 길로 바뀌며, 색은 템플릿에서 가져오고, 글자는 장식용 채움이 됩니다. 디자인된 이미지는 남지만 더 이상 그 사진의 이야기는 아닙니다.

019는 변환된 모든 프레임에 원본 고유의 정체성 단서가 최소 세 가지 남도록 요구합니다. 외곽선, 자세, 방향, 비례, 겹침, 음형, 피사체 사이의 거리 등이 그 단서가 됩니다. 기하는 대담해도 관객은 어떤 장면이 다시 이야기되고 있는지 알아볼 수 있어야 합니다.

```text
원본 사진 → 피사체와 관계 파악 → 정체성 단서 고정 → 3–5색 추출 → 재구성 → 조판 → 검수
```

## 019의 시각적 원칙

- **인식 우선:** 그래픽 긴장감을 만들기 전에 피사체와 관계를 보존합니다.
- **최소 세 가지 정체성 단서:** 외곽선, 자세, 비례, 방향, 겹침, 음형이 함께 작동합니다.
- **원본에서 가져온 3–5색:** 예시나 템플릿이 아니라 현재 사진에서 팔레트를 만듭니다.
- **양형·음형과 스케일:** 큰 색면, 단단한 면 분할, 간결한 곡선, 여백으로 시선의 경로를 만듭니다.
- **절제된 인쇄 감각:** 가벼운 망점, 종이결, 인쇄 어긋남은 평면적 위계를 돕고 광택 있는 3D 효과를 대신하지 않습니다.
- **에디토리얼 타이포그래피:** 제목과 마이크로카피가 기하, 시각적 무게, 공간 리듬에 참여합니다.

## 네 가지 출력, 하나의 인식 체계

네 가지 모드는 하나만 또는 여러 개를 함께 선택할 수 있습니다. `1`, `1+3`, `1、2、4`, `전체`라고 답하면 Skill이 중복을 제거하고 1→4 순서로 실행합니다. 각 모드는 별도 작업 폴더에 독립적으로 출력되며 한 장의 모음 이미지로 합치지 않습니다. `전체`는 원본 한 장당 PNG 7개(일반 모드 각 1개＋배경화면 4개)를 만듭니다. 크기는 모드별로 표시해 같은 답변에서 지정할 수 있고, 지정하지 않은 일반 모드는 원본에 맞춥니다. 문구는 기본적으로 선택한 모드가 공유하며 모드별 지정도 가능합니다.

| 모드 | 크기 규칙 | 결과물 |
| --- | ---: | --- |
| `top-bottom` | 원본 적응형 | 위에는 원본 사진, 아래에는 019 일러스트. 각 패널이 원본의 전체 크기를 유지하며 정확히 50/50으로 나뉩니다. |
| `left-right` | 원본 적응형 | 왼쪽에는 원본 사진, 오른쪽에는 019 일러스트. 각 패널이 원본의 전체 크기를 유지하며 정확히 50/50으로 나뉩니다. |
| `design-only` | 원본 적응형 | 원본 사진은 보이지 않고 완성된 변환 일러스트 한 장만 출력합니다. 원본 비율과 크기를 유지합니다. |
| `wallpaper-pack` | 기기별 네 가지 크기 | 휴대전화, iPad, 데스크톱, 어린이용 스마트워치 PNG를 각각 출력합니다. |

짝을 이루는 모드의 사진은 절제된 색 보정과 필요한 범위의 환경 확장만 적용해 사실성을 지킵니다. 디자인 단독 및 배경화면 모드에서는 사진이 피사체, 관계, 색, 문구의 근거가 되지만 결과에 직접 나타나지는 않습니다.

### 배경화면 세트: 한 가족이지만 한 장의 이미지는 아닙니다

배경화면 세트에는 몰래 적용되는 기본 크기가 없습니다. 일반 기기 프리셋인 휴대전화 `1440×3200`, iPad `2048×2732`, 데스크톱 `3840×2160`, 스마트워치 `1024×1024`를 선택하거나 기기명을 붙인 사용자 지정 크기를 입력합니다.

- **연결형 세트(권장):** 먼저 iPad 기준 작품을 생성해 승인합니다. 나머지 세 기기에는 원본 사진과 승인된 동일 기준 작품을 함께 참조로 주고 각 기기에 맞게 새로 구성합니다.
- **독립형 세트:** 각 기기는 원본 사진만 참조하며 더 자유롭게 탐색할 수 있습니다.

연결형은 팔레트, 그래픽 문법, 인쇄 감각, 타이포그래피 리듬을 공유하지만 피사체 위치, 위계, 글자, 안전 영역은 기기마다 다시 해결합니다. 하나의 기준 이미지를 잘라 쓰거나 참조를 순서대로 연쇄 전달하지 않습니다.

## 문구는 반드시 이미지에 속해야 합니다

생성 전에 자동 문구, 사용자 지정 문구, 무문자 출력 중 하나를 선택하고, 앞의 두 경우에는 목표 언어나 지역도 정합니다. 자동 문구는 ‘기억’, ‘꿈’, ‘여행’처럼 어디에나 붙는 단어에 기대지 않습니다. 눈에 보이는 사실, 관계의 긴장, 근거 있는 함의를 읽고 관객이 사진을 다시 보게 만드는 제목을 찾습니다.

제목은 ‘무관한 이미지 교체 테스트’를 통과해야 합니다. 다른 사진에도 똑같이 잘 어울린다면 이 이미지의 문구가 아닙니다. 마이크로카피는 무작위 일련번호나 가짜 아카이브 표기로 공간을 채우지 않고 같은 의미의 핵심을 확장해야 합니다.

사용자가 완성 문구를 주면 그대로 유지합니다. 방향이나 수정 가능한 초안일 때만 대상 독자, 목적, 필수 표현, 어조, 함의를 보존한 뒤 자연스럽게 재창작합니다.

언어 우선순위:

```text
목표 시장 또는 독자 > 지정한 출력 언어 > 지시문 언어; 모두 불분명하면 생성 전에 질문
```

일본어판은 자연스러운 일본어와 일본어 줄바꿈 규칙을, 한국어판은 자연스러운 현대 한국어와 정확한 띄어쓰기를, 영국판은 영국 영어를 사용합니다. 아랍어판은 자연스러운 현대 표준 아랍어, 올바른 글자 결합, 오른쪽에서 왼쪽으로 흐르는 구성을 사용합니다. 외모로 국적을 추측하지 않으며 가짜 외국어 문자를 사용하지 않습니다.

## 정확한 기하는 스크립트가, 일러스트는 이미지 생성이 맡습니다

`scripts/compose_panel.py`는 계획, 정확한 50/50 래스터 합성, 최종 크기, 검수를 담당합니다. SVG나 프로그램 색면을 실제 비트맵 생성의 대체물로 사용하지 않습니다.

```bash
python3 scripts/compose_panel.py --plan --layout top-bottom --source photo.png
python3 scripts/compose_panel.py --plan --layout left-right --size 2560x1440
python3 scripts/compose_panel.py --audit result.png --layout design-only --size 2048x2048
```

정확한 상하 캔버스는 전체 높이가 짝수여야 하고, 좌우 캔버스는 전체 너비가 짝수여야 합니다. 홀수 크기를 몰래 바꾸지 않습니다.

## 경계와 신뢰

- 현재 사진만 현재 작업의 콘텐츠 원본으로 사용하며 다른 입력, 과거 결과, 번들 예시를 빌리지 않습니다.
- 원본과 매개변수가 같아도 호출할 때마다 새 작업 폴더를 만듭니다.
- 최종 결과물은 PNG 비트맵이며 SVG, HTML, Canvas, 프로그램 드로잉 대체물이 아닙니다.
- 설정된 비트맵 브리지는 정제된 상태만 출력하며 공급자, 엔드포인트, 헤더, 인증 정보, 프롬프트, 서버 응답 본문을 노출하지 않습니다.
- 선택한 일반 모드마다 파일 1개를 반환하고, `wallpaper-pack`을 선택하면 독립 배경화면 4개를 추가합니다. `전체`는 원본 한 장당 PNG 7개를 네 개의 동급 모드 폴더에 저장하며 모음 이미지로 합치지 않습니다.

로컬 합성에는 Python 3와 Pillow가 필요합니다. 안전한 비트맵 브리지는 Python 3.11 이상의 `tomllib`을 사용합니다. 이미지 생성에는 내장 래스터 생성 기능이 있는 호스트 에이전트 또는 이미 설정된 호환 래스터 경로가 필요합니다.
